# sim/dc-static

DC static characteristics of the I/O cell, PVT-FULL (T1 item 5, analog; family of #42).
One `klt sim` request, `request.json`, 45 corners: 5 MOS corners x VDDIO 1.08/1.20/1.32 V
x -40/27/125 C (`klt sim --dry-run` reports `unit_count: 45`). Each process corner is a
bundle of the matching MOS, poly-resistor and diode sections, because the cells use `rppd`
and the antenna diodes as well as the thin-oxide MOS devices. The three requests here are
generated by `gen_dc_static.py`, which builds that `corners` block from the one PVT-FULL
table (`sim/pvt_full.py`) rather than restating it; CI checks both that the committed
requests reproduce (`gen_dc_static.py --check`) and that every committed `sim/` request
agrees with the table (`scripts/ci/check_corner_bundles.py`).

## Joint driver/ESD sizing (issue #130)

Local single-corner probes (ss/1.08 V/125 C, the binding corner for Ron and for T-24, and
ff/1.32 V/-40 C, the minimum-Ron corner), then the 45-corner fleet run above.

**Why width alone cannot close T-08.** The MOS-only Ron spreads 46.6-110.8 ohm (2.38x) for
pull-up and 40.3-86.1 ohm (2.14x) for pull-down over PVT-FULL, wider than the 2x window of
40-80 ohm. Scaling the width to bring the maximum under 80 ohm puts the minimum under 40 ohm
(for example 28u -> 56u gave 52.1 / 23.0 ohm at the two corners). A series `rppd` (about 18 ohm
at `w=10u l=0.5u`; it barely moves with the `res_wcs`/`res_bcs` corner) in each output leg
compresses the ratio, at the price of a wider output device (`XMp` 54u, `XMn` 22u).

**T-24 breakdown at the binding corner (ss/1.08 V/125 C, first-cut cells, fF).** Each row is
the drop in pin capacitance when that one element is removed from the netlist. The sum is
not the total: removing an element also removes its junction-bias coupling.

| Element removed | pad = 0 | pad = VDDIO/2 | pad = VDDIO |
|---|---|---|---|
| (none, total) | 108.9 | 119.3 | 126.2 |
| `XDp1` primary diode (10u x 10u) | 57.2 | 63.5 | 75.0 |
| `XMn1` grounded-gate NMOS (20u) | 13.4 | 11.7 | 10.6 |
| `XMp` driver PMOS (28u) | 12.8 | 14.5 | 17.1 |
| `XMn` driver NMOS (14u) | 9.4 | 8.2 | 7.4 |
| `XResd` (removes receiver, `XDp2`, `XMn2`) | 9.0 | 14.1 | 8.7 |
| `XMclamp` | 0 | 0 | 0 |

The primary diode is 60% of the pin capacitance; widening the driver to fit T-08 adds about
20 fF, so T-24 only closes by shrinking `XDp1`.

The 5 x 5 point passed 45/45 on the fleet but with 0.64 fF of margin at pad = VDDIO/2 (fs/1.32 V/125 C,
99.36 fF), which is not a margin; the recorded design uses `XDp1` 4.5 x 4.5 (worst 96.4 fF).

replace the 45-corner run.

**What this costs.** `XDp1` is now 20 um^2, one fifth of the first-cut 100 um^2. It is not the 35 um^2 `diodevdd_2kv`/`diodevss_2kv` pad diode DR-0008 sized: `XDp1` is
the `dpantenna` antenna-diode model (reverse-direction use, rs about 8.5 kohm at 20 um^2), so a T-25
transient on it would not be credible. No ESD-transient simulation has been run, so T-25 is neither
shown nor refuted. See DR-0017.

## Rows and measurements

All step measurements carry `limits` straight from `spec/target-spec.md`; the spec is
not relaxed. Names are `<step>.<measurement>` in the report.

| Row | Step(s) | Measurement | Bound |
|---|---|---|---|
| T-06 | `drv_nl`, `drv_ld` | `t06_voh_droop_v` (VDDIO - V(pad), driving high), `t06_vol_v` | <= 0.1 V, unloaded and at 1 mA |
| T-08 | `drv_ld` | `t08_rout_up_ohm`, `t08_rout_dn_ohm` (chord resistance at 1 mA) | 40-80 ohm |
| T-07, T-28 | `lk_0`, `lk_5`, `lk_10` | `t07_t28_ipin_a`: pin current, driver tristated, pulls off, pad at 0, VDDIO/2, VDDIO | <= 1 uA |
| T-28 | `pu_on`, `pd_on` | `t28_rpu_ohm`, `t28_rpd_ohm` at VDDIO/2 | 10-20 kohm |
| T-24 | `cap_0`, `cap_5`, `cap_10` | `t24_cpin_ff`: imaginary admittance / (2 pi 500 MHz) at pad = 0, VDDIO/2, VDDIO | <= 100 fF |
| T-11 | `rx_up`, `rx_dn` + derived | `t11_hyst_mv` = abs(up trip - down trip) | <= 60 mV |

Test conditions chosen here, not given by the spec (flagged for ratification):

- **1 mA DC load** for T-06/T-08. The spec gives no load current. 0.1 V / 1 mA = 100 ohm, so
  the T-08 80 ohm bound implies the T-06 droop bound.
- **1 uA** for T-07 and the T-28 tristate leakage. T-07 says "no DC path to a termination"
  and T-28 gives no leakage number; 1 uA is above leakage and below any termination.
  T-07's structural half is the netlists: the only resistors on `PAD` are the weak
  pulls (`XRpu`, `XRpd`, each behind a gated switch) and the ESD series resistor,
  which leads to the receiver gates.
- **T-24 is an extracted-capacitance estimate** from the model small-signal admittance at
  500 MHz, labelled as such. The PDK `bondpad` is an empty placeholder, so no bond pad
  is in it; post-layout PEX is out of scope. It covers the whole pin: ESD, tristated
  driver drains and receiver.
- **T-11** is a structural check: a DC sweep of a memoryless inverter pair cannot show
  hysteresis unless the cell has positive feedback, which is what this detects.

Pin assembly: driver and primary ESD stage on `PAD`, receiver behind the ESD series
resistor on `PADI`. The assembly itself is another issue.

Scope: every row here is `BOTH` (channel and test configuration); no channel model is used.

## Files

- `tb_dc_static.cir` top level; `.include`s the cells from `design/` and the benches.
- `tb_drive.cir` (T-06/T-08), `tb_pin.cir` (T-07/T-24/T-28), `tb_rx_hyst.cir` (T-11).
- `request.json` the one request. `options.fail_on_diagnostic: ["nonconvergence"]` grades
  a corner whose operating point did not converge as `inconclusive`, never pass/fail.
- `gen_dc_static.py` **generates all three requests** here (`request.json`,
  `request_2kv.json`, `request_esd_diode.json`) from one description; the generated JSON
  stays committed, as in the other `sim/` families. `request_2kv.json` was a hand copy of
  `request.json` with nothing checking that the 12 steps stayed equal (#203), so an item-5
  edit could leave the DR-0018 re-run measuring the old set; both now share one `DC_STEPS`
  list. Edit the generator, never the JSON:

  ```bash
  python3 -I sim/dc-static/gen_dc_static.py            # rewrite the three requests
  python3 -I sim/dc-static/gen_dc_static.py --check    # exit 1 if a committed one is stale
  ```

  CI runs `--check` (`scripts/ci/check_local.sh`), so a hand-edited request fails the build.

## Reproduce

```bash
sim/harness/common/fetch-pdk.sh && source sim/harness/env.sh
SG13G2_TOOLS_CACHE=$PWD/sim/build/cache sim/harness/common/build-osdi.sh
python3 -I sim/dc-static/gen_dc_static.py --check       # requests fresh against the generator
klt sim sim/dc-static/request.json --dry-run            # 45 units, backend batch
klt sim sim/dc-static/request.json --format json --report-out /tmp/dc-static-report.json
```

The second command goes to the batch fleet. A record is a new `records/<stamp>/` directory
holding the report; never edit an earlier one.

## ESD pad diode against T-24 (DR-0018, issue #147)

`tb_esd_diode.cir` + `request_esd_diode.json` extract pad C (0, VDDIO/2, VDDIO) and forward
dynamic R of the `sg13g2_esd.lib` pad diodes and the `dpantenna` baseline at 45 corners.
`design/aib_pad_esd_2kv.spice` swaps `XDp1` for `diodevdd_2kv`; `tb_dc_static_2kv.cir` +
`request_2kv.json` re-run the dc-static set on it (the committed netlist is unchanged).
Result: T-24 worst 108.9 fF against 100 fF; T-06/T-07/T-08/T-11/T-28 unchanged. Record
`records/20261110T084631Z/`; decision `spec/decisions/0018-dedicated-esd-diode-capacitance-vs-t24.md`.
Run both with `--wait-for-capacity 600`; `batch.capacity_wait_s` in all three generated
requests is 600 to match (`request.json` carried a stale 1800 until #203).
