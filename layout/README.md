# layout

I/O cell and I/O column stream for T1 item 2 (layout, analog partition). Rows: T-22
(55 um pitch), T-23 (area per wire), DR-0007 (pitch, pad), DR-0010 (column and skew
matching).

**Status of this stream: it exists, regenerates, and passes structural checks. It is not
extraction evidence, and its LVS against the item 1 netlists is `match` for the digital partition and for the four analog cells**
([`lvs/`](lvs/README.md), #40, #70). DRC is recorded in [`records/`](#drc-records); parasitic
extraction of the four drawn I/O cells is in [`pex/`](pex/README.md) (T1 item 7, analog), where
the extraction itself is clean but the extracted netlist cannot be simulated on this PDK, so
`7.analog` stays `unmet`.

The digital partition's routed stream (`klt place-and-route` of the synthesized data path) is
in [`pnr/`](pnr/README.md).

## Files

| File | What |
|---|---|
| `gen_io_column.py` | the generator; the only source of the stream |
| `aib_io_column.gds` | committed stream, written by the generator (no timestamps, byte-reproducible) |
| `check_io_column.py` | structural checks: unit cell 55 x 100 um, column length, mirror symmetry about the column centre, gap-free abutment, no device shape under the pad opening |
| `record_stats.py` | writes `stats/`: `klt stats` JSON per cell and `stats/t22-t23.json` |
| `attest_item2.py` | runs the regenerate-and-check work, then writes `../signoff/attest/item2-analog.json` (and `item2-digital.json`) with `klt signoff --attest 2` |

Provenance: every shape comes from `gen_io_column.py`; nothing is hand-drawn. Device
type, W, L, ng and the net on each terminal are repeated from `design/*.spice` in the
generator, and the run aborts if they disagree with those netlists.

## Regenerate

From the repo root, with the pinned grader (`signoff/KLT_VERSION`):

```bash
K="uvx --from klayout-tools==$(cat signoff/KLT_VERSION)"
$K python -I layout/gen_io_column.py -o layout/aib_io_column.gds
$K klt diff layout/aib_io_column.gds <(git show HEAD:layout/aib_io_column.gds)   # equal after a clean regenerate
$K python -I layout/check_io_column.py layout/aib_io_column.gds
python3 -I layout/record_stats.py
$K python -I layout/attest_item2.py analog     # rewrites signoff/attest/item2-analog.json
```

CI has no klayout stack wired for this, so the generator run is not CI-checked; CI re-grades
the manifest, which re-hashes the committed stream against the citation. The generator
needs only `klayout` (it ships in the klt environment) and the repo's `design/` netlists;
no PDK install is read.

## What is drawn

Cells: `aib_io_tx` and `aib_io_rx` (unit cells, 55 x 100 um, each with its own pad, the
`aib_pad_esd` structure and the `aib_tx_data` driver or `aib_rx_data` receiver),
`aib_io_tx_clk` / `aib_io_rx_clk` (the clk and clkb cells: two unit cells abutted),
`aib_io_column_tx` / `aib_io_column_rx` (24 slots each) and the top `aib_io_column` (the
TX column then the RX column).

- **Assembly choice.** The bond pad is the `PAD` of `aib_pad_esd`. The driver output is on
  `PAD`; the receiver input is on `PADI`, behind the series resistor. The TX cell leaves
  `PADI` on the secondary diodes only. The assembled I/O-cell reference
  netlists for LVS are generated by [`lvs/gen_reference.py`](lvs/README.md).
- **Column (DR-0010, DR-0016).** Slots 0..23: 11 data wires, clk, clkb, 9 data wires,
  **both spares**. Wires 0..21 run monotonically along the column -- data bits 0..19 on wires
  0..19, the two spares as wires 20 and 21 -- so repairing a fault at bit `pos` is a two-cell
  move of bits `pos..19` toward the spares, which is what DR-0016 decides ("Spares sit at one
  end of the I/O column, not at both ends"). The clk/clkb pair sits at the centre of the 22
  I/O cells, the matched span of the clock tree under the DR-0010 Amendment of 2026-11-01
  ("symmetric about the centre of the 22, not of the 20 data cells"); slots 11 and 12 of 24 are
  that centre. Odd slots are mirrored about their own vertical centre line, so neighbours abut
  mirror-to-mirror and the column **geometry** is mirror-symmetric about its centre (slot k and
  slot 23-k); `check_io_column.py` verifies that layer by layer. Only the slot *assignment* is
  asymmetric, and it may be: every non-clock slot holds the same unit cell at the same parity,
  so which wire a slot carries is carried by its `TM1lbl` label, not by its geometry -- which is
  why `check_io_column.py` also reads the slot labels and fails unless there are 20 data + 2
  spare + CLK + CLKB of them, the two spares are adjacent at one end, CLK/CLKB hold the two
  centre slots, and the wires run monotonically. The mirror order (spares at the slot-0 end) is
  equally compliant; the high-slot end was chosen only because it makes the wire numbering
  ascend with x.
  The shared `OE`/`PUN`/`PD` controls and the `VDDIO`/`VSS` rails run across each cell edge to
  edge on Metal3 and join by abutment. The cells carry no clock input in the analog
  partition (the DDR registers are in the digital data path), so the "balanced clock tree"
  here is only the central placement of the clk/clkb cells; their `DIN` stubs are mirror
  images of each other. Any clock tree to the data path belongs to the digital flow.
- **Length (DR-0007).** 20 data wires span 20 x 55 = 1100 um. The column is 24 slots =
  1320 um because it adds the two AIB spare wires (DR-0003) and the clk/clkb pair.
- **Pad (DR-0007).** Passivation opening 40 x 40 um (>= 30 um), TopMetal1 2 um beyond it,
  a Metal3-Metal5 landing stack beneath. The pad occupies the top 44 um of the cell; every
  device is below it (y < 54 um), so nothing sits under the pad. The pad is inside the 55 x
  100 um box, so T-23 is measured with the pad included, which is the conservative reading.
- **Routing.** Devices are placed by hand-chosen rows in the generator; nets are routed
  by a deterministic maze router on a 0.8 um grid (Metal2 vertical, Metal3 horizontal).
  The unit cells route to completion (no unrouted terminal), and a connectivity trace over
  the metal stack finds no short between the labelled nets `PAD`, `VDDIO`, `VSS`, `OE`,
  `PUN`, `PD` and `DIN`/`DOUT`. That trace is not LVS: opens and wrong connections are not
  excluded.

## Measured, and what is not

`stats/t22-t23.json` (from `klt stats` of the drawn cells, labelled layout-measured and
pre-extraction): unit-cell pitch 55.0 um, abutted pair 110.0 um (55.0 um each), area per
wire 5500 um2 (55 x 100 um bounding box, pad included). T-22 and T-23 sit exactly at
their limits; they are met, with no margin, and the 80 um fallback is not invoked. The
bounding box of a cell that is defined to be 55 x 100 um (the `prBoundary`) says the
cell was drawn to that box; the contents are what must fit, and they do (every drawn
shape is inside it). The verdict of record for both rows is the item 8 aggregate
(`measurements/characterization-report.md`), which cites this record through
`measurements/row-evidence.json`; the numbers here are its input, not a second grading.

### DR-0017 regeneration (#140)

The generator's device table follows the merged DR-0017 netlists: `Mp` 54 fingers and `Mn` 22
fingers (w = 1 um each) with drains on the internal nets `DP` / `DN`, two series `rppd` legs
(`Rsp`, `Rsn`, 10 um x 0.5 um, `DP` / `DN` to `PAD`), and `Dp1` 4.5 x 4.5 um. `Mn` moved to the
row above `Mp` and the two legs sit right of it, because 54 + 22 fingers do not fit in one 55 um row.

T-22, `LAYOUT` evidence (layout-measured, pre-extraction): the regenerated `aib_io_tx` and
`aib_io_rx` still fit the 55 um pitch. Over the device layers (`Activ`, `GatPoly`, `NWell`, `pSD`,
`M1`, `PolyRes`) the x extent of `aib_io_tx` is 2.63 .. 53.77 um, so the cell is 1.2 um clear on the
right and 2.6 um on the left; the highest device shape is at y = 48.4 um, below the pad plate
(y >= 54.2 um). No shortfall, so the 80 um fallback (DR-0008) is not invoked and no spec was changed.
Whole-cell DRC is clean (`records/20261110T082915Z`) and column LVS matches (see `lvs/README.md`).

T-25, `LAYOUT` half only: the drawn `Dp1` is 4.5 x 4.5 um (20.25 um2, was 100 um2), the two
series legs are 10 um wide each, and `Mn1` and the clamp are unchanged. This is drawn area and
width, not an ESD level; no discharge-path metal sizing was done here.

Not established by this stream, each its own issue: ERC (#41),
extracted parasitics and skew (#42, #44), the ESD level T-25 (diode and clamp drawn at
the schematic sizes, but supply and discharge-path metal widths are not sized for 0.5 A,
and the deck has no pad or ESD coverage, 2AMLogic/klayout-tools#3854), T-24 pad
capacitance. The DRC result is in [DRC records](#drc-records); it comes from a partial
curated deck and says nothing about pad, ESD or latch-up rules.

### Predriver pull-up regeneration (#187, 2026-11-13)

PR #164 widened the TX predriver NOR pull-ups `Mnr1p` and `Mnr2p` to `w=8u ng=4` in
`design/aib_tx_data.spice` / `design/aib_tx_clk.spice` but did not touch the layout, so the
generator's self-check failed (`AssertionError: Mnr1p`) and the stream could not be regenerated at
all. The device table now carries both at four 2 um fingers.

Placement: the two pull-ups are 1.14 um wider each, and with the 2.0 um device gap row 33 used,
`Mnr2p`'s n-well bulk tap landed on top of `Mn` at x = 28.0 - a 0.01 um metal1 overlap between
`Mn`'s drain stripe and the tap that tied `DN` to `VDDIO`. `check_io_column.py` caught it as
`each resistor's two ends are on separate metal clusters, neither on a rail (50.50,34.40)` (the
`Rsn` leg, whose `DN` end was then on the `VDDIO` cluster). The fix is placement only: `Mnd1p`
keeps its x and the three gaps behind it close from 2.0 um to 1.2 um, which ends the row-33 pmos
chain at 26.81 um, clear of `Mn`. Nothing in `design/`, `spec/` or either checker was changed.

T-22 / T-23, `LAYOUT` evidence (layout-measured, pre-extraction): unchanged. Over the device
layers (`Activ`, `GatPoly`, `NWell`, `pSD`, `M1`, `PolyRes`) the x extent of `aib_io_tx` is still
2.63 .. 53.77 um (2.63 um clear on the left, 1.23 um on the right) and the highest device shape is
still at y = 48.43 um, below the pad plate at y >= 54.2 um; the widened devices grow into the row,
not past its ends. The cell contents fit the 55 x 100 um box, so the 80 um fallback (DR-0008) is
not invoked and no spec row was touched. `stats/t22-t23.json` re-measures 55.0 um pitch and
5500 um2 per wire, both still met with no margin.

Downstream, all re-run on the new stream: structural checks clean
(`check_io_column.py` exit 0), whole-cell DRC clean (`records/20261113T112710Z`), the five LVS
compares `match` and the negative control `mismatch` (`lvs/README.md`), ERC `erc_status: clean`
with 0 findings, `stats/` and `signoff/attest/item2-analog.json` regenerated, and
`signoff/block-manifest.signoff.json` re-graded: `2.analog`, `3.analog`, `4.analog` and
`11.analog` all read `met`, on the same 18 / 22 T1 total as before.

### Spare placement (#248, 2026-11-13)

DR-0016 ("both spares at one end") is ratified, but `build_column` labelled the slots
`SP0, D0..D9, CLK, CLKB, D10..D19, SP1` -- one spare at **each** end. The cell count, pitch,
length and symmetry were already right (22 I/O cells per direction plus the clk/clkb pair,
slots 24, length 1320 um); what was wrong was which slot carried which wire, and no check read
the slot order, so it passed. The order is now
`D0..D10, CLK, CLKB, D11..D19, SP0, SP1` and `check_io_column.py` has four new checks that read
the `TM1lbl` slot labels (count by class, spares adjacent at one end, CLK/CLKB on the two centre
slots, wires 0..21 monotonic). Run against the pre-fix stream those four fail (two per column,
exit 1) while every pre-existing check still passes; against the regenerated stream all 38 pass.

Seeded check (run locally with the pinned klt; not in CI, which installs no klayout). Rewriting
only the 24 label strings in a scratch copy of the column and re-running the checker: the
committed order passes (so the rewrite harness itself perturbs nothing), and each of five seeded
wrong orders is caught -- spares at both ends, clk/clkb off centre by one slot, two data wires
swapped with the spares still at one end, a data wire duplicated and one missing, and the two
spares adjacent but in the middle of the run. The mirror order
(`SP1, SP0, D19..D11, CLKB, CLK, D10..D0`) passes, as the Column bullet above says it should.

Nothing moved. Only the 24 label *strings* per column cell changed: the non-text geometry of
every cell is bit-identical to the pre-fix stream (independently digested over all layers with
text excluded) and all 54 label positions are unchanged. The `klt signoff` geometry digest does
cover text (`_canonical_shape_token` renders a text shape as `text <Text.to_s()>`, which carries
the string), so the stream hash, the geometry digest and
`signoff/attest/item2-analog.json` all change and were regenerated.

Downstream, all re-run on the new stream: structural checks clean (`check_io_column.py` exit 0,
38/38), whole-cell DRC clean (`records/20261113T231304Z`), the five LVS compares `match` and the
negative control `mismatch` (`lvs/README.md`), ERC `erc_status: clean` with 0 findings, and
`signoff/attest/item2-analog.json` plus `signoff/block-manifest.signoff.json` regenerated:
`2.analog`, `3.analog`, `4.analog` and `11.analog` all still `met`, 16 / 22 T1 `met` as before.
Every one of those re-runs is byte-identical to its predecessor apart from the stream hash, which
is the evidence that a label rename is what it looks like. `stats/t22-t23.json` and the item 8
report re-derive unchanged (`klt stats` measures bounding boxes; a label at the cell centre moves
nothing), so they are not re-committed. No spec row, bound or decision record was touched.

**Re-run separately (#253):** `pex/records/20261113T130842Z/` (the four `klt extract` reports
under item 7.analog) bound the pre-fix stream hash, and re-running needs `PDK_ROOT`
